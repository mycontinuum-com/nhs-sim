# Explore home readings in Home Health

Open **At home** on <a href="/control/">the neighbourhood map</a> and launch Home Health. The wearable dashboard and patient Messages are separate apps at the same location.

## Select a resident and inspect readings

Open the resident selector and find any synthetic person by name or SIM identifier. Choose a person to view their devices and observations. Use the day or week controls to change the reading period, and expand **Recorded readings** to inspect dated values and quality labels.

A missing value remains missing. Charts and summaries use the selected resident's recorded data. They do not assess health or recommend treatment.

## Connect a simulated watch

If the resident has no active activity watch, choose **Connect simulated watch**. The first activity reading is due after 10 simulation minutes, followed by hourly readings. Advance time using **Simulation controls** in the fixed bottom bar, then inspect the new reading.

No physical device or external Apple or Withings account connects to the simulator. Reconnecting an already active activity watch does not create another device. An organiser can simulate device disconnection; missing readings stay visible as missing data.

## Read and reply to practice messages

Return to the home desktop and launch **Messages**. Select the same resident to see delivered practice conversations. Reply where the practice allows replies. See [Messagey messaging](./messaging.mdx) for the delivery simulator and practice inbox.

## Connect an agent

Open the **Wearables** group in the <a href="/docs/explorer/">API explorer</a> and authorize with your team key. The key must include `wearables` scope. New teams created without a `site` restriction include this scope; joining an existing team preserves its permissions.

Read a resident's devices with `GET /api/sites/wearables/devices?patient=SIM-000006`. Read their recorded values with `GET /api/sites/wearables/readings?patient=SIM-000006`. Fresh simulator seeds include activity, resting heart rate, and sleep history for this resident. Existing published populations retain their stored history and can return empty lists. Connect a simulated watch to generate new activity readings.

Add `metric=steps`, `metric=heart-rate`, or `metric=sleep` to filter readings. Each response contains `items`, `total`, `offset`, `limit`, and the simulation time `now`. Requests default to 100 records; use `limit` from 1 to 500 and increase `offset` to retrieve further pages. Omitting `patient` returns matching records across your team's world.

Read each item's `data` for its metric, value, unit, quality, and observation time. Timestamps use Unix milliseconds. Preserve `null` values and their quality labels when a device disconnects. A missing reading is not zero.

To generate readings for another resident, post this JSON to `/api/sites/wearables/actions`:

```json
{
	"type": "connect_device",
	"patientId": "SIM-000003",
	"title": "Home activity watch"
}
```

Post `{"paused": true, "advanceMinutes": 10}` to `/api/clock`, then request `/api/sites/wearables/readings?patient=SIM-000003` to retrieve the first activity reading.

Use `GET /api/sites/wearables/view?patient=SIM-000006` when you also need shared service records and events. See the [API reference](./api.mdx) for authentication and clock operations. The <a href="/api/openapi.json">OpenAPI JSON</a> includes the wearable request parameters and response schemas.
